# CS230OperatingPlatforms
This repository is an example of the things I learned throughout this course.

Briefly summarize The Gaming Room client and their software requirements. Who was the client? What type of software did they want you to design?
The Gaming Room has an Android application "Draw IT or Lost IT" which was based on a 1980s game show. They wanted the development company to make the currently working application into a cross platform application for iOS, MAC, and Windows.

What did you do particularly well in developing this documentation?
My strongest point in this documentation was the evaluation section where I discussed various needs based on different approaches. These approaches talked about the needs for different categories when using Mac, Linux, Windows, and Mobile Devices.

What about the process of working through a design document did you find helpful when developing the code?
One of the most difficult section of software development is the initial planning and building. So, for me the summary was the most helpful because it forced me to have some sort of fundamental starting point. After that I can dig into solution, refining it as I go.

If you could choose one part of your work on these documents to revise, what would you pick? How would you improve it?
Funny enough, I would change the summery, and focus on making slightly more detailed examples of why I wanted implement certain languages, tools, etc. Those detailed examples would be based on client needs and vision.

How did you interpret the user’s needs and implement them into your software design? Why is it so important to consider the user’s needs when designing?
The baseline for user needs was to have a fun and smooth running game application. I did my best to implement those needs by selecting designs that would allow for smooth cross platform operations. Another thing I did was think about scalability and how we could add so many features to this game after the initial release. The user is the reason the product is used, which is why I get to have fun doing my job. They're the most important part of the whole process.

How did you approach designing software? What techniques or strategies would you use in the future to analyze and design a similar software application?
I like the Agile approach to software development due to the high level of uncertainty with development. I tried to not focus too much on exactly how certain sections of development would be carried out due to the uncertainty. I will continue to use that approach because I think its important to have a fundamental basis that can be versatile. Setting many aspects of software design in stone will reduce that projects agility when it comes to adapting to changes.
